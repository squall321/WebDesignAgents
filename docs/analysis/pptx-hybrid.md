# 하이브리드 PPTX — 텍스트가 편집되는 슬라이드 (PLAN §9 ③안)

기존 PPTX 는 스테이지 캡처 1장을 풀블리드로 얹은 그림 슬라이드였다. 글자를 고칠 수 없다.
하이브리드는 **배경만 캡처하고 글자는 네이티브 텍스트박스로 얹는다**. 파워포인트에서 문안을
직접 고칠 수 있고, 배경의 도형·차트·카드 장식은 캡처 그대로 유지된다.

```python
export_pptx(build_dir, "index.html", out, format_id="short-9x16",
            stills=stills, notes=notes, mode="hybrid")   # mode 기본값은 "image"(종전 동작)
```

## 1. 왜 런타임 휴리스틱인가

씬 템플릿(`web/templates/*.jsx`)에 `data-pptx-role` 같은 표식을 달면 분류는 정확해지지만,
템플릿 파일은 동시 작업 영역이라 손댈 수 없다. 그래서 **렌더된 DOM 을 그대로 읽는** 방식을 택했다.
부수 효과로 템플릿이 늘어나도(현재 가로 7 + 세로 4 + 확장) 추출기는 그대로 동작한다.

## 2. 추출 규약 (`src/wdrender/pptx_text.py`)

### 리프 텍스트 규칙

채택 조건은 **"직속 자식으로 공백 아닌 텍스트 노드를 가진 요소"** 하나다. 채택된 요소의
자손은 건너뛴다. `<div>앞말 <span>강조</span> 뒷말</div>` 은 부모 하나만 상자가 되고,
강조 span 은 그 상자의 **run** 으로 흡수된다(색·굵기 보존). 컨테이너 중복 상자가 생기지 않는다.

- 좌표는 **콘텐츠 상자** — `getBoundingClientRect()` 에서 테두리·패딩을 뺀다.
  칩·필처럼 패딩이 큰 요소도 글자 위치가 맞는다(예: `padding: 20px 40px` 필 → x+40, y+20).
- 줄 수는 내용 Range 의 클라이언트 사각형을 top 기준(폰트 크기 60% 허용오차)으로 묶어 센다.
  **한 줄이면 `word_wrap=False`** — 대체 폰트가 더 넓어도 접히지 않는다.
  **여러 줄이면 `word_wrap=True`** — 설계 폭 안에서 원래대로 접힌다.
- `line-height` 가 수치면 `paragraph.line_spacing` 으로 정확히 옮긴다(`normal` 은 미지정).
- **`<br>` 과 `white-space: pre-line` 의 개행은 `a:br`(파워포인트 줄바꿈)로 옮긴다.**
  이 처리가 없으면 `{lead}<br />{tail}` 이 `…뒤섞이고취합은…` 처럼 붙어버린다(실측 확인).
  `white-space: normal` 구간의 연속 공백은 브라우저와 같게 하나로 접는다.

### 제외 대상과 사유

제외된 요소는 **숨기지도 않는다** — 배경 캡처에 원래 모습 그대로 남으므로 화면은 손실 없다
(대신 그 글자는 편집 불가). 채택 술어와 숨김 술어가 같은 통과에서 결정되기 때문에
"뽑은 것만 정확히 사라진다"가 성립한다.

| 사유 | 판정 | 근거 |
| --- | --- | --- |
| `rotate/skew` | 누적 변환 행렬의 b·c 가 0 이 아님 | 텍스트박스는 회전 없이 얹으므로 위치·모양이 어긋난다 |
| `opacity` | 누적 불투명도 < 0.95 (`MIN_OPACITY`) | 진입 애니메이션 도중 — 불투명 텍스트로 승격하면 화면이 달라진다 |
| `hidden` | 조상까지 `display:none` / `visibility:hidden` | 화면에 없다 |
| `zero-size` | 폭·높이 < 1px | 렌더되지 않음 |
| `offstage` | 스테이지 사각형과 교차 없음 | 슬라이드 밖 |

`translate`·`scale` 은 제외하지 않는다. `getBoundingClientRect()` 가 이미 반영하고,
폰트 크기는 누적 배율만큼 곱해 보정한다.

### 배경에서 글자를 지우는 법

`visibility:hidden` 은 **쓰지 않는다**. 요소의 배경·테두리·그림자까지 함께 지워
칩·필·카드가 배경 캡처에서 통째로 사라지기 때문이다(실측: short_v1 `행동` 씬에서
CTA 필 2개가 사라져 상자 밖 35,318px 손실). 대신 글자색만 투명으로 내린다.

```css
color: transparent !important
-webkit-text-fill-color: transparent !important
text-shadow: none !important
border-color: <실측값> !important      // 테두리 기본색이 currentColor 라 같이 사라지는 것 방지
```

원래 inline `style` 문자열을 `data-wda-pptx-s0` 에 저장했다가 다음 호출 첫머리에 되돌린다.

### 역할 분류 (`classify_role`)

두 포맷(1920×1080 / 1080×1920)의 타입 스케일은 모두 **짧은 변 1080px** 기준으로 저작돼
있어, `rel = font_px / min(stage_w, stage_h)` 로 정규화하면 가로·세로를 같은 자로 잰다.

| 조건 | 역할 | 실측 근거 |
| --- | --- | --- |
| `rel ≥ 0.050` | title | 가로 sectionTitle 56 (0.052) · hero 112 / 세로 title 72 · hero 96 |
| `0.031 ≤ rel < 0.050` 이고 (굵기 ≥ 500 또는 y ≤ 30%) | subtitle | 가로 subtitle 36/500 |
| `0.031 ≤ rel < 0.050` 이고 그 외 | body | 세로 본문 40/400 |
| `rel < 0.031`, 굵기 ≥ 700, y ≤ 20% | label | 킥커 가로 26/700 · 세로 32/700 |
| `rel < 0.031`, y ≥ 88% | caption | 푸터 가로 24 · 세로 32 |
| `rel < 0.031`, 굵기 ≥ 700 | label | 카드 제목 33/800 · 단계 번호 27/800 |
| 나머지 | body | 가로 본문 26/400 |

중간 밴드에 가로 subtitle(36/500)과 세로 body(40/400)가 함께 살아 크기로는 갈리지 않는다.
굵기 500 이 그 경계다. 한계 — 대형 지표값(세로 `근거` 씬의 320px "100")도 크기 규칙상 title 로
분류된다. 역할은 도형 이름(`wda-title-3`)에만 쓰이고 배치에는 영향이 없어 산출물은 멀쩡하다.

## 3. 좌표 변환

스테이지 px → 슬라이드 EMU 는 순수 비례다.

| 포맷 | 스테이지 | 슬라이드 | EMU/px | pt/px |
| --- | --- | --- | --- | --- |
| wide-16x9 | 1920×1080 | 12,192,000×6,858,000 (13⅓×7.5in) | 6350.0 (양축) | 0.5 |
| short-9x16 | 1080×1920 | 6,858,000×12,192,000 (7.5×13⅓in) | 6350.0 (양축) | 0.5 |

두 포맷 모두 x·y 배율이 같아 종횡비 왜곡이 없다. 폰트 크기는 `px × EMU/px ÷ 12700`
(96px → 48pt, 320px → 160pt).

**좌표 오차 실측** — PPTX 를 다시 열어 도형 좌표를 px 로 환산하고, 같은 시각에 DOM 에서
독립 재추출한 좌표와 비교했다.

| 대상 | 상자 수 | 좌표 오차 최대 |
| --- | --- | --- |
| delib_v2 (가로 8슬라이드) | 125 | **7.87e-05 px** |
| short_v1 (세로 5슬라이드) | 55 | **7.38e-05 px** |

오차 상한은 구조적으로 0.5 EMU = 1/12700 in = 7.87e-05 px 다. EMU 는 정수 격자이고
1px = 6350 EMU 로 정확히 떨어지므로, 남는 것은 소수 px 좌표를 정수 EMU 로 반올림한 값뿐이다.

## 4. 폰트 대체 매핑

python-pptx 는 **폰트 임베딩을 지원하지 않는다**(PPTX 의 `p:embeddedFontLst` 를 쓰지 않으며,
쓰더라도 EOT 변환과 라이선스 문제가 남는다). 그래서 텍스트는 **열람 PC 에 설치된 폰트**로만
렌더된다. 렌더 무대의 Pretendard 계열을 윈도우 기본 한글 폰트로 내린다.

| 무대 폰트(CSS) | PPTX 지정 | 비고 |
| --- | --- | --- |
| `Pretendard Variable` / `Pretendard` | 맑은 고딕 | 현행 테마 `raw.font.base` 의 1·2순위 |
| `Noto Sans KR` | 맑은 고딕 | 테마 3순위 |
| `Apple SD Gothic Neo` | 맑은 고딕 | macOS 저작본 대비 |
| `sans-serif` / `system-ui` / `-apple-system` | 맑은 고딕 | 제네릭 |
| `serif` / `NanumMyeongjo` | 바탕 | |
| `monospace` / `Consolas` / `D2Coding` | Consolas / D2Coding | |
| `Arial` / `Helvetica` | Arial | |
| 매핑 없음 | 맑은 고딕 (기본) | |

`a:latin` 만 지정하면 파워포인트가 한글을 다른 폰트로 흘려보낸다. **`a:ea`(동아시아
타입페이스)도 같은 이름으로 지정**한다(`_set_font_name`).

굵기는 이분법이다 — CSS weight ≥ 600 → `bold=True`. Pretendard 의 800/700/500 구분은
맑은 고딕의 2단(regular/bold)으로 눌린다.

## 6. 테스트 (`tests/test_pptx_hybrid.py`, 24개)

합성 1씬 엔트리(제목+강조 span / 패딩·배경·그림자 필 / 2줄 본문 / 회전 텍스트 / 반투명
텍스트 / 하단 캡션 / `<br>` 줄바꿈)로 브라우저를 실제로 띄워 검증한다.

- 리프 규칙 — 강조 span 이 독립 상자로 중복되지 않고 부모의 run 으로 들어간다
- 좌표 — 코드에 박은 CSS px 와 콘텐츠 상자 좌표가 정확히 일치(필의 padding 20/40 반영)
- 줄바꿈 — `윗줄<br/>아랫줄` → run 3개(가운데 `br`), PPTX 에서 `윗줄\v아랫줄`
- 제외 — 회전 `rotate/skew`, 반투명 `opacity`
- 숨김 — 상자 밖 변화 0px, 필 배경색(20,40,160) 잔존, 회전·반투명 텍스트 잔존, 원복 확인
- PPTX — 문자열 5개 일치, 좌표 EMU(=px×6350) 일치, run 색 3개, 48pt, `a:ea` 지정,
  한 줄 `word_wrap=False` / 두 줄 `word_wrap=True`
- image 모드 — 텍스트 프레임 0, 풀블리드 그림 1장, 노트 유지
- `mode` 오타는 `ValueError`

## 7. 한계

1. **폰트 임베딩 불가.** python-pptx 는 폰트를 파일에 넣지 못한다. 맑은 고딕이 없는 PC
   (macOS·리눅스)에서는 파워포인트/뷰어가 임의 폰트로 대체하고, 자폭이 달라지면 한 줄
   텍스트는 상자를 넘치고 여러 줄 텍스트는 줄 수가 바뀔 수 있다. 배경 캡처는 Pretendard
   원본이므로 **글자만 미묘하게 다른 얼굴**이 된다.
2. **자간·굵기 축 손실.** 가변폰트 800/700/500 은 bold 2단으로 눌리고 `letter-spacing`
   은 옮기지 않는다.
3. **복잡 레이아웃.** 회전·기울임 텍스트, 진행 중인 애니메이션(불투명도 < 0.95),
   `overflow:hidden` 으로 잘린 텍스트, 세로쓰기는 배경에 구워진 채 남는다(편집 불가).
   SVG `<text>` 는 현행 템플릿이 쓰지 않아 미검증이다.
4. **한 상자 = 한 문단.** `<br>`·`pre-line` 개행은 `a:br` 로 살리지만 전부 한 문단 안이다.
   문단별 정렬·들여쓰기·글머리표는 재현되지 않는다.
5. **z 순서.** 텍스트박스는 배경 그림 위에 일괄로 얹힌다. 원본에서 텍스트 위를 덮던
   요소(오버레이·마스크)가 있으면 겹침 순서가 뒤집힌다.
6. **✕ 같은 기호 글리프**는 Pretendard 에 없어 브라우저 폴백으로 그려진다. 폴백 폰트가
   바뀌면 배경 캡처가 미세하게 달라진다(§5 의 525px 차이가 그것이다). 텍스트로 승격되면
   이번엔 PPTX 폴백을 타므로 모양이 또 달라질 수 있다.
7. **CLI·MCP 미배선.** `wda render` 와 MCP/web 렌더 잡은 아직 image 모드만 호출한다
   (`src/wdpipeline/cli.py`·`src/wdmcp/jobs.py`·`src/wdweb/runs.py` 는 동시 작업 영역).
   `export_pptx(..., mode="hybrid")` 직접 호출로만 쓸 수 있다.
