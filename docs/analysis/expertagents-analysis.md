## SUMMARY
ExpertAgents(/home/koopark/claude/ExpertAgents)는 스마트폰 부품 도메인을 631개 마이크로 전문가 페르소나로 초세분화한 AI 상담·회의 시스템이다. 각 전문가는 knowledge/{expert_id}/expert.yaml 한 파일(SSOT)에 완성형 system_prompt를 포함한 페르소나, in_scope/out_of_scope 경계, 라우팅 앵커, 관련 전문가 위임 규칙까지 선언적으로 정의되고, pydantic 모델(src/expertcore/models/expert.py)로 엄격 검증된다. 핵심 설계 철학은 "서버는 LLM을 호출하지 않는다"로, MCP 서버(src/expertmcp/server.py, FastMCP stdio)가 페르소나+RAG 근거 패키지와 claude_instructions 지시문을 봉투(envelope)로 반환하면 클라이언트 Claude가 그 전문가를 연기한다. 회의체는 결정론적 상태머신(src/expertcore/meetings/engine.py)이 진행을 강제한다. 회의 유형 5종(brainstorm/design_review/tradeoff/dfmea/rca)이 각각 RoundSpec 리스트(templates.py)로 선언되며, 발언 순서(fixed/round_robin/moderator_pick), 인용 의무, 조기 종료 조건을 서버가 검증한다. 턴마다 stance(propose~rebut~accept)와 구조화 산출물(idea/finding/decision/action_item/open_issue), 인용(known_refs 화이트리스트로 환각 인용 차단)이 붙고, 폐회 시 minutes.py가 결정·액션아이템·미응답 반박(합의 연출 방지)을 집계한 마크다운 회의록을 생성한다. 기술 스택은 Python 3.12 + pydantic v2 + Qdrant(로컬) + BGE-M3 임베딩 + FastMCP이며, OpenAI/vLLM 연동은 없고 Anthropic API 서버구동 모드는 설계 문서(docs/02-design/04-meeting-engine.md §6)에만 있는 미구현 옵션이다. 코어(expertcore)가 MCP 어댑터와 FastAPI 어댑터(src/expertapi/routers/meetings.py)에서 공유되는 구조라, 웹디자인 페르소나 회의체는 expert.yaml 내용과 MEETING_TEMPLATES만 교체하면 엔진·스토어·회의록·MCP 계층을 그대로 재사용할 수 있다.

## KEY_FACTS
- 전문가 정의 SSOT: knowledge/{expert_id}/expert.yaml 1파일. 구조 = id/abbr(카드ID 접두어, 대문자 2~4자)/name_ko/name_en/category/status(draft|pilot|active|deprecated) + persona{title, career_background, speaking_style, system_prompt(완성형, MCP가 그대로 반환)} + expertise{in_scope 5~15개, out_of_scope('→ 위임대상' 표기), boundary_statement} + routing{keywords_ko/en, patterns(정규식), example_questions(라우터 앵커), anti_examples(오분류 감점)} + related_experts[{id, relation, when_to_refer}] + meeting{default_role, stance} + maintenance. 검증 모델: src/expertcore/models/expert.py (pydantic StrictModel, extra=forbid)
- 지식카드 포맷: knowledge/{id}/cards/*.md — YAML frontmatter(id: PW-C-001, expert_id, title, type: concept/decision 등, confidence: fact|heuristic|expert-judgement, tier, sources[{ref, locator}], fact_refs, tags, version, review_status) + 마크다운 본문. python-frontmatter로 파싱. 전문가 631명, 카테고리 15종(soc/mem/rf/pcb/passive/pwr/disp/cam/sh/mech/sim/rel/misc/sw/xd, src/expertcore/models/common.py CATEGORIES). id 접두어=category 강제
- 회의 엔진: src/expertcore/meetings/engine.py MeetingEngine — create/next_speaker/submit_turn/close. 발언 순서는 LLM 재량이 아니라 템플릿+발언 이력으로 서버가 결정론적으로 강제. 참가 확정 순서=발언 순서. 라운드 전이 = 예정 발언 수 충족 또는 decision 산출물 제출 시 조기 종료(allow_early_close)
- 회의 유형 5종 템플릿: src/expertcore/meetings/templates.py MEETING_TEMPLATES — brainstorm(diverge→build_on→converge), design_review(present→review→rebuttal→verdict, Go/Conditional-Go/No-Go 판정), tradeoff(advocate→attack→score 1~5점 매트릭스→decide 가중합), dfmea(failure_modes→rate S·O·D→prioritize RPN→actions), rca(problem 5W2H→five_why→fishbone 6M→verify_plan). RoundSpec = {name, instruction, speaker_order: fixed|round_robin|moderator_pick, cycles, citation_required, allow_early_close}
- 턴 스키마: src/expertcore/models/meeting.py MeetingTurn — {turn_no(엔진 채번), round_no, role: expert|moderator|user|system, expert_id, stance: propose|support|concern|rebut|question|accept|summarize, content_md, citations[{ref, quote}], artifacts[{type: idea|finding|decision|action_item|dfmea_row|open_issue, content, owner_expert_id}]}. 모더레이터는 기술 주장 생성 금지(조직화만), user/system 턴은 순서·인용 검증 없이 기록
- 환각 인용 차단: 브리핑으로 실제 전달한 카드ID/chunk_id만 known_refs 집합(src/expertmcp/meeting_session.py MeetingClientState)에 축적하고, submit_turn에서 citations.ref가 known_refs 밖이면 거부. citation_required 라운드에서 인용 없으면 거부
- 회의록 렌더러: src/expertcore/meetings/minutes.py render_minutes — 참가자 표 / 라운드별 발언 요약 표(턴·발언자·태도·요지·인용) / 결론(decision 집계) / 액션아이템 표 / 인용 근거 목록(ref dedupe+턴 역참조) / 미해결 쟁점(open_issue 산출물 + rebut 이후 타 발언자 accept가 없는 턴 자동 추출 — 합의 연출 방지)
- 영속화: src/expertcore/meetings/store.py MeetingStore — data/meetings/{YYYYMMDD-HHMMSS}_{type}_{slug}_{id4}/ 아래 meta.json + turns.jsonl(append) + minutes.md. 파일이 진실이며 요청마다 엔진을 재조립해 resume 가능
- MCP 서버: src/expertmcp/server.py — FastMCP(mcp>=1.0) stdio, LLM 호출 없음. 상담 툴 7종(list_experts, find_expert, consult_expert, search_facts, get_expert_profile, session_info, session_reset) + 회의 툴 5종(meeting_start, meeting_get_briefing, meeting_submit_turn, meeting_status, meeting_close) + 대리모델 업로드 툴 2종. 모든 응답은 봉투 {ok, data, session, claude_instructions, error{code,message,hint}} (src/expertmcp/envelope.py)
- claude_instructions 조종 패턴: envelope.py의 MEETING_RULES — '당신이 모더레이터 겸 각 참가 전문가를 연기한다. 매 턴 meeting_get_briefing→페르소나로 발언 생성→meeting_submit_turn 기록. 인용 없는 기술 주장 금지. 이견은 stance=rebut으로 드러내고 합의를 서두르지 마라'. 상황별 지시문 함수(consult_instructions, meeting_briefing_instructions 등)로 다음 행동을 매 응답에 지시
- 페르소나 델타 전달: 세션/회의 원장(delivered_personas)으로 최초 1회만 system_prompt 전문(delivery: full), 이후 recall 모드로 토큰 절약. fact 마커 [F#]는 세션/회의 전역 연번
- 기술 스택: Python>=3.10(실제 3.12), pydantic>=2.7, pydantic-settings, structlog, PyYAML, python-frontmatter, qdrant-client(로컬 경로 모드), BGE-M3 임베딩(FlagEmbedding, optional [gpu]), TEI 리랭커 optional, typer CLI(erag), FastAPI optional [api](포트 8710), mcp>=1.0 [mcp]. 테스트용 FakeEmbedder(EXPERTS_FAKE_EMBEDDER). 설정은 EXPERTS_ 접두 환경변수(src/expertcore/config.py). OpenAI/vLLM 연동 없음. Anthropic API 서버구동 모드(meeting_run_auto)는 docs/02-design/04-meeting-engine.md §6 설계만 있고 미구현
- 참가자 자동 선정: src/expertcore/routing/semantic_router.py — 앵커(example_questions+in_scope+이름) 임베딩 max-sim 0.75 + 키워드 가중 0.25 - anti_examples 감점. meeting_start에서 participants 미지정 시 needs_confirmation으로 추천 후보만 반환하는 2단계 확정 흐름
- FastAPI 미러: src/expertapi/routers/meetings.py — POST /meetings(추천/생성), GET /meetings, GET /meetings/{id}(next_speaker 포함), POST /meetings/{id}/turns, POST /meetings/{id}/close, GET /meetings/{id}/minutes(PlainText). MCP와 동일한 expertcore 엔진 공유
- MCP 등록: .mcp.json.example — type: stdio, command: .venv/bin/expertmcp, env로 EXPERTS_EXPERTS_ROOT/EXPERTS_DATA_DIR/EXPERTS_EMBEDDING_DEVICE 주입. 상세 설계 문서: docs/02-design/01-mcp-server.md, 04-meeting-engine.md(라운드·브리핑·행동규약 전체), 05-knowledge-pipeline.md

## REUSABLE_PATTERNS
- expert.yaml SSOT 페르소나 포맷 전체를 도메인만 바꿔 재사용 — 웹디자인이면 카테고리(타이포그래피/컬러·브랜드/레이아웃·그리드/UX리서치/접근성/모션/프론트엔드 구현성 등)로 나누고, persona.system_prompt(완성형)+speaking_style+in_scope/out_of_scope 경계+related_experts 위임 규칙+meeting.default_role/stance 구조를 그대로 유지
- MEETING_TEMPLATES 선언적 라운드 템플릿 — RoundSpec 자체가 도메인 무관. design_review(발표→관점별 리뷰→반박→Go/No-Go 판정)는 디자인 크리틱에, tradeoff(옹호→교차공격→점수 매트릭스→가중합 결정)는 시안 A/B/C 선정에, brainstorm(발산→build-on→수렴)은 컨셉 도출에 거의 무수정 재사용 가능. 새 회의 유형은 MeetingType enum과 템플릿 dict에 항목 추가만으로 확장
- 클라이언트 구동 MCP 오케스트레이션 패턴 — 서버는 순서·검증·기록만 강제하고 LLM(클라이언트 Claude)이 브리핑 페르소나로 전원을 연기. 봉투의 claude_instructions 필드로 매 응답마다 다음 행동을 지시하는 방식은 LLM API 키 없이 Claude Code/MCP 환경에서 즉시 동작
- 결정론적 next_speaker + submit_turn 검증(차례/라운드/인용 필수/known_refs) — 발언 순서 조작과 환각 인용을 서버에서 차단하는 구조. 웹디자인 회의에서도 '브리핑으로 전달된 디자인 원칙 카드/레퍼런스만 인용 가능' 규칙으로 그대로 적용
- stance 프로토콜(propose/support/concern/rebut/question/accept/summarize)과 미응답 반박 자동 추출 — 페르소나 간 이견을 강제로 드러내고 가짜 합의를 방지하는 장치. 디자인 취향 충돌(예: 미니멀 vs 표현적)을 쟁점으로 남기는 데 유효
- artifacts 구조화 산출물 집계형 회의록 — 회의록의 모든 표가 턴에 첨부된 조각(decision/action_item/finding/open_issue)의 집계라서 렌더러(minutes.py)가 도메인 독립적. 디자인 결정 로그·수정 액션아이템·미해결 쟁점이 자동 문서화
- meta.json+turns.jsonl+minutes.md 파일 영속화와 요청별 엔진 재조립 — 세션 끊김에도 회의 resume 가능, DB 불필요
- 시맨틱 라우터의 앵커+키워드+anti 3요소 점수와 2단계 참가자 확정(추천→사용자 확정) — 회의 주제로 참가 페르소나를 자동 추천하는 흐름 재사용
- expertcore(코어)/expertmcp(MCP 어댑터)/expertapi(FastAPI 어댑터) 3계층 분리 — 동일 엔진을 웹 UI 백엔드와 MCP 양쪽에 노출하는 구조
- 페르소나 full/recall 델타 전달 + [F#] 인용 마커 연번 — 다인 회의에서 토큰 예산을 관리하는 패턴

## INTEGRATION_POINTS
- meeting_start(topic, type, participants?) → participants 없으면 {status:'needs_confirmation', recommended:[{expert_id,name_ko,score,reason}]}, 있으면 {status:'created', meeting_id(UUID4), rounds:[{round_no,name,speaker_order,cycles,citation_required}], next_speaker}
- meeting_get_briefing(meeting_id) → {round:{round_no,name,instruction,citation_required}, speaker:{role,expert_id,name_ko}, persona:{delivery:'full'|'recall'|'none', system_prompt}, cards:[{card_id,title,confidence,body_md}](L1 top3), facts:[{marker:'[F#]',ref:chunk_id,text,citation,confidence}](L2 top5), recent_turns:[{turn_no,speaker,stance,gist}], speaking_rules:{stance_enum,artifact_types,length_hint(200~1500자),citation_note}}
- meeting_submit_turn(meeting_id, round_no, role, content_md, expert_id?, stance?, citations:[{ref,quote}], artifacts:[{type,content,owner_expert_id?}]) → 성공 {accepted:true, turn_no, round_no, next_speaker} / 거부 {ok:false, error:{code:'TURN_REJECTED', message, hint}}
- meeting_status(meeting_id) → 라운드 인덱스/총 라운드/턴 수/recent_turns/next_speaker/delivered_personas/known_refs_count. meeting_close(meeting_id) → {minutes_path, decisions, action_items, turns_total}
- 모든 MCP 응답 봉투 계약: {ok, data, session:{active_expert, delivered}, claude_instructions(다음 행동 지시문), error:{code,message,hint}|null} — 웹 플랫폼에서 자체 오케스트레이터를 만들 때도 이 지시문 채널 유지 권장
- REST 미러(FastAPI, 포트 8710, X-API-Key 선택): POST /meetings, GET /meetings, GET /meetings/{id}, POST /meetings/{id}/turns, POST /meetings/{id}/close, GET /meetings/{id}/minutes — 웹 UI가 MCP 없이 직접 붙을 수 있는 입출력 계약
- 지식 SSOT 계약: knowledge/{expert_id}/expert.yaml + cards/*.md(frontmatter)를 src/expertcore/registry/loader.py가 로드, 'erag validate'로 스키마 검증, 'erag index'로 Qdrant 색인 — 웹디자인 지식카드도 같은 파이프라인에 투입 가능
- 환경 계약: EXPERTS_ 접두 환경변수(.env), EXPERTS_EXPERTS_ROOT(지식 루트)/EXPERTS_DATA_DIR(회의·인덱스 저장)/EXPERTS_FAKE_EMBEDDER(임베딩 없이 구동) — 임베딩 모델 없이도 회의 엔진·회의록 계층은 완전 동작
- MCP 클라이언트 등록: .mcp.json.example 형식(type:stdio, command:.venv/bin/expertmcp, env 주입) — 새 플랫폼용 서버도 동일 형식으로 Claude Code에 연결
- LLM 자동 실행이 필요하면 docs/02-design/04-meeting-engine.md §6의 ServerModeOrchestrator 설계(Anthropic messages.create, system=페르소나별 격리 프롬프트, 검증 실패 시 repair_hint로 1회 재생성)를 구현 지점으로 사용 — 현재 코드에는 없음
