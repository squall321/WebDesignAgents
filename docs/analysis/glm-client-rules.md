## SUMMARY
HWAXPortal 자체는 LLM을 직접 호출하지 않는 씬 프록시(인증+SSE 릴레이)이고, 실제 vLLM 호출은 형제 레포 HWAXAgentServer(:9009, langchain ChatOpenAI)와 ReportArchive(httpx 직접)가 한다. GLM 서빙은 두 환경으로 갈린다. dev 박스는 HWAXPortal/docs/start-dev-vllm.sh가 Apptainer로 로컬 vLLM 0.23.0(:8000/v1, Qwen2.5-7B-AWQ, served-name qwen2.5-7b-dev, 무인증)을 띄우고, 프로덕션(cae00)은 상암 B300의 OpenAI 호환 vLLM(http://10.198.143.137:10000/v1, 모델 GLM-5-2, Bearer 키)을 쓴다. 상암 GLM 서버의 기동 설정 파일은 이 레포에 없다(상암 관리자 소관, --reasoning-parser glm45 여부 미확인). 설정의 정본은 ReportArchive/backend/.env의 LLM_BASE_URL/LLM_MODEL/LLM_API_KEY이며, HWAXPortal/infra/env-kits/apply-envs.sh가 @FROM_RA:KEY@ 마커로 이를 읽어 다른 서비스 .env에 '없는 키만 추가' 방식으로 상속시킨다. GLM 구조화 출력 실적은 response_format={"type":"json_object"}(ReportArchive, 400 폴백 포함)까지만 검증됐고 guided_json/json_schema 실사용은 0건(문서상 권고만)이다. GLM-5.2는 vLLM 0.23.0 스트리밍 경로에서 tool_calls를 유실하는 결함이 있어 프로덕션은 LLM_DISABLE_STREAMING=1(완결 응답)로 운용하며, reasoning 제어는 반드시 extra_body의 chat_template_kwargs.reasoning_effort 경유다.

## GAPS
- 상암 B300 vLLM의 서빙 기동 설정(기동 플래그·--reasoning-parser glm45·generation-config 기본값)이 이 코드베이스에 없음 — 상암 관리자 소관이라 guided_json/json_schema(구조화 출력 서버 지원) 가능 여부가 미검증. DEPLOY-RUNBOOK-2026-07-21.md §4의 raw curl 진단을 먼저 수행해야 함
- GLM-5-2 대상 guided_json/response_format json_schema 실사용 실적 없음(json_object까지만 검증) — WebDesignAgents가 스키마 강제 구조화 출력이 필요하면 직접 검증 필요하며 400 폴백 경로 필수
- GLM 실 접속값(특히 LLM_API_KEY)은 cae00 운영 박스의 ReportArchive/backend/.env에만 존재 — 이 dev 박스에서는 상암(10.198.143.137) 도달 자체가 불가하여 dev 개발은 로컬 Qwen vLLM으로만 가능
- 공용 LLM 클라이언트 라이브러리/패키지 미존재 — ReportArchive llm.py는 RA backend의 app.config에 결합돼 있어 import 불가, 복사·이식 필요
- apply-envs.sh MAP에 WebDesignAgents 항목이 없음 — 킷 파일 신규 작성 + MAP 1줄 추가 필요(기존 계약상 '없는 키만 추가'이므로 이후 값 변경은 대상 .env 직접 수정)
- vLLM 로컬 인스턴스는 16GB VRAM 박스에서 GPU_MEM_UTIL=0.80으로 운용 중 — WebDesignAgents가 같은 박스에서 GPU를 추가로 쓰면 vLLM 재기동 OOM 위험(restart-vllm.sh의 EngineCore 좀비 정리 절차 참조)
