## SUMMARY
이 스택은 3층 구조다. (1) support.js — .dc.html을 부팅하는 DC 런타임으로, React/ReactDOM 18.3.1 UMD와 @babel/standalone 7.29.0을 CDN(SRI 검증, window.__resources로 오프라인 대체 가능)에서 지연 로드하고, <x-dc> 템플릿({{expr}} 보간, sc-for/sc-if, helmet, x-import)을 안전한 미니 표현식 해석기로 컴파일해 React 트리로 렌더한다. (2) animations-v2.jsx — window 전역에 노출되는 타임라인 엔진으로, rAF 클럭 + 이징/보간 원자(animate/interpolate) + 씬 시퀀싱(SceneStage/SceneSwitch) + 타임 스트레치(nat 필드) + 프레임 단위 seek 프로토콜(data-om-seek-to-time-frame, sync 커밋은 ReactDOM.flushSync) + SVG foreignObject 래핑과 @font-face data-URL 인라인까지 담당한다. (3) hwax-scenes.jsx — 씬을 localTime의 순수 함수로 작성하고 내용(STEPS/CASES/PERSONAS 배열)과 표현 코드를 분리한 모범 사례다. 실제 mp4 인코딩(WebCodecs VideoEncoder)은 이 파일들에 없고 호스트 편집기가 수행하므로, 새 플랫폼은 게스트 측 계약(exportable svg 속성 + seek 이벤트 + fonts-inlined 신호)을 그대로 이용해 exporter를 자체 구현해야 한다. (a) Playwright 헤드리스 export는 완전히 가능하다 — 조건은 http 서빙(x-import가 fetch 사용), CDN 의존성 확보 또는 __resources 번들, svg[data-om-exportable-video-with-duration-secs] 마운트와 data-om-fonts-inlined="true" 대기, 씬이 전부 localTime 기반(결정적)일 것, 프레임마다 detail:{time, sync:true}로 CustomEvent를 svg에 dispatch한 뒤 즉시 캡처(스크린샷+ffmpeg 경로가 가장 단순, WebCodecs 경로는 Chromium 필수). (b) PPT 정적 슬라이드 추출도 구조적으로 적합하다 — 씬이 시각의 순수 함수이고 frame-match 계약(진입/퇴장 효과가 progress 0과 1에서 0) 덕분에 씬별 특정 시각으로 seek하면 완성된 정지 화면이 나오며, 1920×1080은 16:9 PPT와 정확히 일치한다. 단 S7처럼 씬 내부에 다단 페이즈(통계 → 페이드아웃 → 타이틀)가 있는 경우가 있으므로 씬 엔트리에 per-scene 정지 시각(still) 메타데이터를 추가해야 하고, 진짜 편집 가능한 PPT를 원하면 동일 데이터 JSON을 소비하는 별도 정적 렌더러(pptxgenjs 등)를 두는 이중 렌더러 구조가 정석이다 — 데이터/표현 분리가 이미 되어 있어 실현 가능하다. 모듈 후보는 engine-core(순수 이징/보간), scene-runtime(SceneStage+seek 프로토콜), scene-template-library(Frame/카드/네트워크/챗봇 목업), design-tokens, scene-data 스키마+검증기, entry 생성기, headless-exporter(영상), slide-exporter(PPT), LLM 추출 파이프라인의 9개로 도출된다.

- 무번들러 window 전역 모듈 배선: x-import from의 순차 로드 + Object.assign(window, {…}) + component-from-global-scope 폴링 — 빌드 스텝 없이 LLM이 생성한 씬 파일을 즉시 실행하는 구조(플랫폼에서는 esbuild 사전 번들로 대체 가능하나, 즉시성 유지 시 이 방식 재사용)
- 오프라인 리소스 번들 훅: window.__resources(URL 치환)/__resourceBlobs(Blob 프리로드)로 CDN 의존을 제거하는 support.js 내장 메커니즘 — 헤드리스 렌더 팜의 네트워크 격리·재현성 확보에 그대로 활용

## INTEGRATION_POINTS
- 입력(콘텐츠): 방법론 문서의 씬 데이터 JSON 스키마 — {core_message, audience, duration_sec, tone, problem{claim,failures[]}, process{steps[{n,name,desc}]}, differentiator{before,rebuttal,after}, cases[{id,title,desc,badge}], closing{values[],cta[]}} — LLM 추출 단계의 출력이자 씬 템플릿 주입 입력
- 입력(구성): window.OM_SCENES — '[{"name":str,"dur":sec, …여분 필드 자유}]' JSON 문자열(≤16KB, 1~50개, dur∈(0,300]) — 및 window.OM_PLAYBACK — '{"mode":"loop"}' | '{"mode":"times","count":1..99}' — 를 엔트리 HTML의 vanilla 인라인 스크립트로 선언, SceneStage에 문자열 그대로 전달. 씬 name은 children 맵 키와 정확히 일치 필수
- 입력(씬 코드): 씬 파일은 window에서 {SceneStage, Easing, animate, …} 구조분해 → 씬 컴포넌트는 {localTime, progress, dur, index, count, scene} props로만 렌더 → 루트 컴포넌트를 window.<이름>에 등록 → 엔트리의 <x-import component-from-global-scope="<이름>" from="./animations-v2.jsx ./scenes.jsx">(순서: 엔진 먼저)와 일치
- 제어(렌더 오케스트레이터→엔진): svg[data-om-exportable-video-with-duration-secs] 요소에 dispatchEvent(new CustomEvent('data-om-seek-to-time-frame', {detail:{time:초, sync:true}})) — sync는 svg의 data-om-sync-seek="true" 광고 확인 후 사용, 반환 즉시 DOM이 해당 프레임 상태. duration은 같은 속성값에서 읽음
- 준비 신호(엔진→오케스트레이터): svg 마운트(= x-import 해석 완료) → document.fonts.ready → svg[data-om-fonts-inlined="true"] — 이 3단계 대기 후 캡처 시작. PlaybackBar 등 편집 크롬은 [data-omelette-chrome] 셀렉터로 숨김
- 출력(영상): 프레임 루프(t=i/fps seek → svg 요소 캡처) → ffmpeg 조립(권장) 또는 페이지 내 XMLSerializer(svg)→Image→canvas→WebCodecs VideoEncoder(Chromium 전용). 중첩 비디오·오디오는 data-om-exportable-video-play-start/end/speed 속성으로 믹싱 정보 수급
- 출력(정적 슬라이드): 씬 엔트리 확장 필드(엔진이 scene prop으로 무가공 전달)에 still 시각 목록을 넣고, 씬별 starts[i]+still로 seek → 캡처 → 16:9 PPTX 조립. 편집형 PPT는 동일 데이터 JSON을 소비하는 별도 정적 렌더러로 생성
- 편집기 연동(선택): 루트에 data-om-timeline-scenes/-playback 속성이 원문 그대로 노출되고 data-om-timeline-scenes-update/-playback-update CustomEvent(detail=새 raw 문자열)로 무리로드 반영 — 새 플랫폼의 타임라인 UI가 이 채널을 그대로 쓰면 트림/재배열/반복 설정이 소스 write-back과 라이브 반영을 동시에 얻음
- 배포/격리: window.__resources = {원본URL: 대체URL}, window.__resourceBlobs = {URL: Blob}을 엔진 로드 전에 주입하면 React/Babel/폰트 CDN 의존 제거 — 네트워크 차단된 헤드리스 렌더 노드의 표준 주입 지점
- 구동 전제: x-import·폰트 인라인이 fetch 기반이므로 file:// 불가, 로컬 정적 http 서버로 서빙. DC 런타임(support.js)은 편집기 스트리밍·write-back용이며 자동 렌더 전용 플랫폼에서는 React+Babel+엔진+씬을 직접 로드하는 순수 HTML 엔트리로 대체 가능(계약은 동일)
