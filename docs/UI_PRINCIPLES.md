# 인터페이스 품질 원칙 — "이 이상 괜찮다고 생각하기 어려운" 수준

사용자 상시 지시 (2026-07-26): 인터페이스 구성 품질을 끝없이 고민하라. 기능이 도는 것과 잘 구성된 것은 다르다. 모든 UI 작업(콘솔·프리뷰·산출물)은 이 문서를 기준으로 자기 심사를 거친다.

## 대원칙 — 구두수선공의 아이들부터 신긴다

이 플랫폼은 "발표자료의 화면 구성"을 심의하는 플랫폼이다. **그 콘솔 자체가 플랫폼이 강제하는 디자인 원칙(토큰·모션 문법·위계·접근성)의 실증이어야 한다.** 콘솔이 평범하면 플랫폼의 설득력이 죽는다.

## 심사 기준 7항

1. **한 화면 한 임무** — 첫 화면에서 사용자가 해야 할 일이 정확히 하나로 보인다(보고서 투입). 결과 화면에서는 프리뷰가 주인공이고 나머지는 보좌한다. 동급 요소 나열 금지.
2. **진행의 서사** — 스피너가 아니라 이야기. 파이프라인 진행은 "지금 무엇이 일어나고 있는가"를 보여준다(단계 이름·현재 작업·심의라면 발언 중인 페르소나). 기다림이 관찰이 되게.
3. **토큰 일치** — 콘솔의 색·타입 스케일·간격·라운드는 hwax-blue 토큰에서만 나온다. 임의 hex·px 금지(산출물과 같은 규율).
4. **모션 문법 일치** — 콘솔의 등장/전환도 플랫폼 모션 문법(rise/pop, easeOutCubic/easeOutBack, 스태거 대역)을 따른다. 과하지 않게 — 모션은 위계 설명 수단이지 장식이 아니다.
5. **접근성은 결격 사유** — AX 페르소나 기준 그대로: 대비 4.5:1, 포커스 가시성, 키보드 완주 가능, 의미 있는 빈 상태·오류 문구(한국어, 원인+다음 행동).
6. **왕복이 중심 무대** — 프리뷰↔대화 수정 루프가 이 제품의 심장이다. 그 화면에서 시선 이동·클릭 수를 최소화하고, 수정 결과(무엇이 바뀌었는지)가 항상 눈에 보이게.
7. **밀도는 브리핑급** — 경영진 브리핑 자료처럼: 여백이 계층이고, 표는 짧고, 숫자는 크고, 잡동사니는 없다.

## 운영 루프 (끝없는 고민의 구현)

- UI 를 바꾸는 모든 라운드는 **페르소나 design_review 심의**(LG 레이아웃·TY 타이포·CB 컬러·AX 접근성·MO 모션 + CD)로 콘솔 스크린샷을 심사받는다 — 산출물과 동일한 규율.
- Conditional-Go 이하면 반영 후 재심사. 회의록은 data/meetings 에 남긴다.
- 새 화면·컴포넌트 추가 시 이 문서 7항으로 자기 점검 후 커밋.
