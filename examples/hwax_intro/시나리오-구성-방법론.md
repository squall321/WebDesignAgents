# 심의 → 소개영상 시나리오 구성 방법론

심의(토론) 결과물을 90초 내외의 소개/요약 영상 시나리오로 변환하는 절차. 
자동화 파이프라인 설계용 참고 문서 (LLM 프롬프트 + 데이터 스키마 기반 구현을 전제).

---

## 0. 원문 해체 (Deconstruct)

- 입력 문서(회의록·의사결정문·아키텍처 문서 등)를 **문장이 아니라 조각으로** 분해한다.
- 분류 축: `주장(Claim)` / `근거(Evidence)` / `사례(Case)` / `수치(Metric)` / `행동유도(CTA)`.
- 영상의 재료는 이 조각들이다. 원문 문장을 그대로 옮기지 않는다.

**자동화 힌트:** LLM에 "다음 문서를 위 5개 축으로 항목화하라"는 추출 프롬프트 → 구조화 JSON.

---

## 1. 단 하나의 메시지 정의 (Single Core Message)

- 영상이 끝났을 때 시청자 머릿속에 **한 문장만** 남는다고 가정하고, 그 문장을 먼저 확정한다.
  - 예: "단일 AI 질의로는 부족하다 → 다중 전문가 심의가 답이다."
- 이후 모든 씬은 이 문장을 뒷받침하는 역할로만 존재한다. 뒷받침 못 하는 내용은 버린다.

---

## 2. 시청자·목적·길이 고정 (Constraints First)

- **누구에게 / 몇 초 / 어떤 톤** 을 가장 먼저 못 박는다. 이게 정보 밀도·속도·구조를 결정한다.
  - 예: 경영진 / 90초 / 브리핑 톤.
- 대상에 따라 서사 순서가 달라진다.
  - 경영진 → "왜 필요한가 → 어떻게 작동 → 믿을 만한가"
  - 실무자 → "어떻게 작동 → 구체 사례 → 한계·주의"

**자동화 힌트:** 이 3개 값을 파이프라인 입력 파라미터로 노출.

---

## 3. 설득 골격에 재배열 (Problem → Solution → Proof)

- 원문 순서가 아니라 **설득 순서**로 조각을 정렬한다.
- 표준 골격:
  1. **문제 / 필요성** — 왜 이게 필요한가 (기존 방식의 한계)
  2. **접근 / 개념** — 우리의 해법은 무엇인가
  3. **작동 방식 / 절차** — 어떻게 돌아가는가
  4. **차별점** — 남과 무엇이 다른가
  5. **실증 / 신뢰** — 실제로 되는가 (증거)
  6. **결론 / 행동유도** — 그래서 무엇을 하라

---

## 4. 씬 분할 — 한 씬 한 메시지 (One Scene, One Point)

- 각 씬은 **단 하나의 주장**만 담는다. 두 가지를 말하려 하면 씬을 쪼갠다.
- 오프닝·클로징 = 감정/각인, 중간 씬 = 논리.
- 통상 5~8개 씬으로 수렴.

---

## 5. 시간 예산 배분 (Time Budgeting)

- 전체 길이를 **중요도 순**으로 나눈다. 균등 분배 금지.
  - 핵심 논증(절차·실증)에 길게, 개념 씬은 중간, 감정 씬(오프닝)은 짧게.
- 씬별 시간 = `기본 낭독 시간 + 여백`.
  - 텍스트 글자 수 → 최소 표시 시간 자동 산정 가능.
  - 성우 내레이션 예정이면 대사 타이밍 여유를 추가로 확보.

**예시 배분 (90초 / 7씬):**

| 씬 | 역할 | 길이 |
|----|------|------|
| 오프닝 | 각인 | 8s |
| 문제 | 필요성 | 13s |
| 개념(심의란) | 해법 | 11s |
| 절차 | 작동 방식 | 18s |
| 차별점(자체교정) | 차별화 | 13s |
| 실증 사례 | 신뢰 | 15s |
| 클로징 | 결론·CTA | 12s |

---

## 6. 추상 → 시각 은유 변환 (Concept → Visual Metaphor)

- 말로 된 개념을 반드시 **눈에 보이는 물체/동작**으로 바꾼다.

| 추상 개념 | 시각 은유 |
|-----------|-----------|
| 단일 답변의 한계 | 챗봇 목업 + 회색 스켈레톤(무성의한 평균답) |
| 여러 전문가 동시 토론 | 중앙 질문 → 다수 노드로 뻗는 네트워크 |
| 라운드 진행 | R1→R2→R3 좌→우 흐름 |
| 만장일치 수렴 | 아바타마다 체크마크 하나씩 점등 |
| 자체 교정 | 오류 태그(빨강) → 반박 → 수용(파랑) |

- 원칙: **명제는 물체로, 변화는 동작으로.**

---

## 7. 근거의 위계 = 모션 타이밍 (Logic via Motion Order)

- "무엇이 먼저 보이고 언제 강조되는가"로 인과·논리를 연출한다.
  - 단계 카드 **순차 점등** = 절차의 순서 자체를 설명.
  - 오류 → 반박 → 수렴의 **등장 순서** = 인과 관계를 시각화.
- 등장 순서와 강조 타이밍이 곧 설명이다. 한 화면에 다 띄우지 않는다.

---

## 8. 구체 증거로 착지 (Land on Specifics)

- 막연한 주장 대신 **구체적 식별자·수치**로 신뢰를 확보한다.
  - 예: 실제 보고서 번호(#14 / #10 / #16), "굴곡반경 0.7R", "전문가 6인 만장일치".
- 마지막 씬은 **행동 유도**로 닫는다 (진입점·다음 단계 명시).

---

## 요약 원칙 (One-liner)

> 문서를 옮기지 마라. → **한 메시지로 압축 → 설득 순서로 재배열 → 씬당 하나씩 → 개념을 시각 은유로 → 시간과 등장 순서로 강조 → 구체 증거로 착지.**

---

## 자동화 설계 메모 (Data-Injection Template)

이 방법론은 **데이터 주입형 템플릿**으로 구현하기 좋다.

1. **씬 부품 고정:** 문제 / 개념 / 절차 / 차별점 / 실증 / 결론 = 재사용 씬 타입.
2. **데이터 스키마 정의:** 각 씬 타입이 받는 배열/필드를 규격화.
   ```jsonc
   {
     "core_message": "단일 AI 질의로는 부족하다 → 다중 전문가 심의가 답이다",
     "audience": "경영진", "duration_sec": 90, "tone": "브리핑",
     "problem":   { "claim": "...", "failures": ["...", "..."] },
     "process":   { "steps": [ { "n": "01", "name": "...", "desc": "..." } ] },
     "differentiator": { "before": "...", "rebuttal": "...", "after": "..." },
     "cases":     [ { "id": "#14", "title": "...", "desc": "...", "badge": "..." } ],
     "closing":   { "values": ["...", "..."], "cta": ["...", "..."] }
   }
   ```
3. **파이프라인:** 심의 결과 → (LLM 추출: 0·1·3단계) → 위 JSON → 씬 템플릿에 주입 → 영상.
4. **자동 처리 가능:** 스키마 추출, 씬 개수/길이 산정(글자 수 기반), 카드 N장 생성.
5. **사람 손이 남는 부분:** 스토리 순서·강조 선택, 카피 톤 다듬기, 오버플로 레이아웃 조정, 신규 다이어그램 유형.

## 기술 스택 (Technology Stack)

이 영상은 촬영·영상편집툴이 아니라 **코드로 매 프레임을 계산해 그리는 방식**으로 만든다. 조합된 기술은 다음과 같다.

### 사용 라이브러리·런타임 (실제 로드되는 의존성)

| 이름 | 버전 | 역할 | 출처(CDN) |
|------|------|------|-----------|
| **React** | 18.3.1 | 화면을 시각 `t`의 함수로 선언, 변경분만 갱신 | `unpkg.com/react@18.3.1` (UMD) |
| **ReactDOM** | 18.3.1 | React 트리를 실제 DOM에 렌더 (`createRoot`) | `unpkg.com/react-dom@18.3.1` (UMD) |
| **@babel/standalone** | 7.29.0 | `.jsx`/TS 문법을 브라우저에서 즉석 트랜스파일 (presets: `react`, `typescript`) | `unpkg.com/@babel/standalone@7.29.0` |
| **Pretendard (Variable)** | 1.3.9 | 한글 웹폰트 (dynamic subset) | `cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9` |
| **DC 런타임** (`support.js`) | 프로젝트 동봉 | `.dc.html` 부팅, 템플릿 파싱, `x-import`로 모듈 로드, React UMD·Babel 지연 로드 | 로컬 파일 |
| **애니메이션 엔진** (`animations-v2.jsx`) | 프로젝트 동봉 | 타임라인·이징·씬 시퀀싱·영상 export | 로컬 파일 |

> 별도 npm 설치·번들러(webpack/vite) 없이, 브라우저가 CDN 스크립트를 직접 불러 실행한다. `support.js`가 React/ReactDOM(UMD)과 Babel을 필요 시점에 로드한다.

### 브라우저 내장 API (별도 라이브러리 아님)

| API | 역할 |
|-----|------|
| **requestAnimationFrame** | 타임라인 클럭 — 초당 ~60회 `t`를 진행시켜 프레임 갱신 |
| **WebCodecs `VideoEncoder`** | 프레임을 브라우저에서 직접 인코딩 → mp4 등 영상 파일 출력 (서버 렌더팜 불필요) |
| **SVG `<foreignObject>` + XMLSerializer** | 매 프레임 DOM을 이미지로 직렬화(폰트 data URL 인라인) → export 입력 |
| **CSS Flex/Grid + `position:absolute`** | 벡터 레이아웃 (해상도 무관, 1920×1080 기준) |

### 1) 렌더링 기반 — 웹 표준
- **HTML + CSS(인라인 스타일) + JavaScript** — 화면 자체가 웹 문서. 모든 요소(카드·노드·텍스트)는 DOM.
- **React** — 화면을 "현재 시각 `t`의 함수"로 선언적으로 표현. `t`가 바뀌면 React가 바뀐 부분만 다시 그림.
- **Babel (standalone)** — `.jsx` 문법을 브라우저에서 즉석 변환. 별도 빌드 과정 없이 브라우저가 바로 실행.

### 2) 애니메이션 엔진 (`animations-v2.jsx`)
- **타임라인 클럭** — `requestAnimationFrame` 루프로 시각 `t`를 0→90초로 흘려보냄. 초당 약 60회 화면 갱신.
- **이징/보간 (Easing / Interpolation)** — `easeOutCubic`, `easeOutBack` 등 수학 함수로 "26px 아래→제자리를 0.7초 동안 부드럽게" 같은 움직임을 계산. `animate({from,to,start,end,ease})(t)`가 핵심 원자.
- **씬 시퀀싱 (SceneStage)** — 여러 장면을 순서·길이대로 이어 붙이고, 각 씬에 자기 시각(`localTime`)을 공급. 씬 길이를 늘리면 같은 모션이 느려지는 **타임 스트레치** 지원.
- **재생 제어** — play/pause, 스크러버(타임라인 드래그), 반복(loop) / N회 재생.

### 3) 씬 로직 (`hwax-scenes.jsx`)
- 각 장면을 **React 컴포넌트 함수**로 작성. `localTime`을 받아 위치·투명도·크기를 계산.
- **데이터 배열 + 렌더링 분리** — `STEPS`, `CASES`, `PERSONAS` 등 내용은 배열, 표현은 그 배열을 도는 코드. (자동화가 가능한 이유)
- **레이아웃** — CSS Flex/Grid + `position:absolute` 좌표. 벡터라 해상도 무관.

### 4) 컴포넌트/구동 방식
- **Design Component (`.dc.html`)** — 단일 파일로 브라우저에서 바로 열리는 컴포넌트 포맷. 씬 목록(`OM_SCENES`)·재생 설정(`OM_PLAYBACK`)을 상단 스크립트로 선언.
- **웹 폰트** — Pretendard(한글) CDN 로드.

### 5) 영상 파일 내보내기 (Export)
- **SVG `<foreignObject>` 직렬화** — 매 프레임의 DOM을 SVG 이미지로 캡처(폰트 data URL 인라인 포함).
- **WebCodecs `VideoEncoder`** — 캡처한 프레임들을 브라우저에서 직접 인코딩해 **mp4 등 영상 파일**로 출력. 별도 서버·렌더팜 불필요.
- 프레임 단위 정확 seek 프로토콜(`data-om-seek-to-time-frame`)로 각 프레임을 정확한 타임스탬프에 캡처.

### 조합 요약

```
[콘텐츠]  심의 데이터(JSON/배열)
   │
[표현]    React 컴포넌트(씬) — localTime → 화면
   │
[구동]    애니메이션 엔진 — rAF 클럭 + 이징 + 씬 시퀀싱
   │
[변환]    Babel(jsx) · 웹폰트 · Flex/Grid 레이아웃
   │
[출력]    화면 재생  ─또는─  SVG 직렬화 + WebCodecs → 영상 파일(mp4)
```

### 자동화 관점 추가 스택 (파이프라인 구현 시)
- **LLM** — 문서 → 구조화 JSON 추출(0·1·3단계), 카피 요약·톤 정리.
- **스키마 검증** — 추출 JSON을 씬 데이터 규격에 맞춰 검증/보정.
- **헤드리스 브라우저**(예: Puppeteer/Playwright) — 사람이 안 열어도 서버에서 씬을 구동해 프레임 캡처·영상 렌더 자동화 가능.
- **TTS(선택)** — 내레이션 음성 자동 생성 후 씬 길이에 동기화.

## 재현용 빌드 스펙 (Build Spec — 다른 AI/툴이 이 문서만 보고 만들 수 있도록)

> 두 가지 재현 경로가 있다.
> **(A) 이 프로젝트의 엔진 파일 재사용** — `support.js` + `animations-v2.jsx`를 함께 받아 씬만 새로 작성. (권장, 빠름)
> **(B) 엔진 없이 처음부터** — 아래 "엔진 계약"을 자체 구현. (라이브러리/프레임워크 자유)

### 파일 구조 (경로 = 같은 폴더)

```
프로젝트/
├─ support.js            ← DC 런타임 (동봉, 수정 금지)
├─ animations-v2.jsx     ← 애니메이션 엔진 (동봉, 수정 금지)
├─ hwax-scenes.jsx       ← 씬 코드 (여기를 편집)
└─ 소개영상.dc.html       ← 엔트리 (씬 목록·재생 설정)
```

### 엔트리 파일 최소 골격 (`.dc.html`)

```html
<!DOCTYPE html><html><head>
  <meta charset="utf-8">
  <script src="./support.js"></script>   <!-- React·Babel을 알아서 로드 -->
</head><body>
<x-dc>
<helmet>
  <!-- 폰트: 반드시 helmet 안에서 로드 -->
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css">
  <style>html,body{margin:0;height:100%;background:#E9EBF1;}</style>
  <!-- 씬 목록: 이름 + 길이(초) -->
  <script>window.OM_SCENES = '[{"name":"오프닝","dur":8},{"name":"문제","dur":13}]';</script>
  <!-- 재생: 무한반복 또는 N회 -->
  <script>window.OM_PLAYBACK = '{"mode":"loop"}';</script>
</helmet>
<x-import component-from-global-scope="IntroVideo"
          from="./animations-v2.jsx ./scenes.jsx"
          style="position:fixed;inset:0" hint-size="100%,100%"></x-import>
</x-dc>
</body></html>
```

- `OM_SCENES`/`OM_PLAYBACK`은 **JSON 문자열**(작은따옴표 안). 씬 `name`은 아래 매핑 키와 정확히 일치해야 함.
- `from`은 **공백으로 구분**해 순서대로 로드(엔진 먼저, 씬 나중). `component-from-global-scope`는 씬 파일이 `window`에 올린 전역 컴포넌트 이름.

### 폰트 배선 (정확히 이렇게)

1. `<link>`는 **helmet 안**에 둔다(문서 상단에서 먼저 로드되도록).
2. 텍스트에 쓰는 `font-family` 리터럴 (폴백 포함):
   ```js
   const F = "'Pretendard Variable', Pretendard, 'Noto Sans KR', sans-serif";
   ```
3. 영상 export 시 폰트가 SVG에 인라인되어야 글자가 깨지지 않는다 → 엔진(`animations-v2.jsx`)이 `@font-face`를 data URL로 자동 인라인. (자체 구현 시 이 단계 필수)

### 엔진 계약 (경로 B에서 재구현해야 하는 것)

엔진은 `window`에 다음을 제공: `SceneStage`, `useTimeline`, `Easing`, `animate`, `interpolate`, `clamp`.

- **SceneStage** — `scenes`(JSON 문자열)·`playback`·`width`·`height`·`bg`와, 자식으로 **{씬이름: 컴포넌트}** 객체 맵을 받는다. 씬을 순서대로 이어 붙이고 총 길이는 각 `dur`의 합.
- **씬 컴포넌트** — 활성 씬은 props로 `{ localTime, progress, dur, index, count, scene }`를 받는다. **자기 시각 `localTime`(0초부터)** 로만 애니메이션한다(전역 시계·`Date.now()` 금지 — export가 프레임 단위 seek이라 결정적이어야 함).
- **animate** — 단일 구간 트윈:
  ```js
  animate({ from, to, start, end, ease })(t)   // t<start면 from, t>end면 to
  ```
  실무 헬퍼:
  ```js
  const A = (t, start, dur, from, to, ease) =>
    animate({ from, to, start, end: start + dur, ease: ease || Easing.easeOutCubic })(t);
  // 예: A(t, 1.0, 0.7, 26, 0) = 1.0초부터 0.7초간 26px→0
  ```
- **Easing** — `linear, easeOutCubic, easeInCubic, easeOutBack, easeInQuad …` (표준 이징 함수 모음).
- **클럭** — `requestAnimationFrame`로 `t`를 진행. `loop`면 끝에서 0으로 되돌리고, `times:N`이면 N회 후 마지막 프레임 유지.

### 씬 작성 최소 예 (`scenes.jsx`)

```jsx
const { SceneStage, Easing, animate } = window;
const A = (t,s,d,a,b,e)=>animate({from:a,to:b,start:s,end:s+d,ease:e||Easing.easeOutCubic})(t);
const F = "'Pretendard Variable', Pretendard, 'Noto Sans KR', sans-serif";

function Opening({ localTime: t }) {
  return (
    <div style={{position:'absolute',inset:0,fontFamily:F,
      display:'flex',alignItems:'center',justifyContent:'center',
      opacity:A(t,0.3,0.8,0,1),
      transform:`translateY(${A(t,0.3,0.8,24,0)}px)`}}>
      <h1 style={{fontSize:96,fontWeight:800,color:'#1428A0'}}>제목</h1>
    </div>
  );
}
function Problem({ localTime: t }) { /* … */ return <div/>; }

function IntroVideo() {
  return (
    <div style={{position:'relative',width:'100vw',height:'100vh'}}>
      <SceneStage width={1920} height={1080} bg="#F6F7FA"
                  scenes={window.OM_SCENES} playback={window.OM_PLAYBACK}>
        {{ '오프닝': Opening, '문제': Problem }}
      </SceneStage>
    </div>
  );
}
window.IntroVideo = IntroVideo;   // ← .dc.html의 component-from-global-scope 와 일치
```
