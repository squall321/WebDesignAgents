## 정의
시나리오 변환 후반부 절차 — 골격을 씬으로 쪼개고 전체 길이를 씬에
배분한다. 두 원칙이 지배한다. **한 씬 한 메시지**, **균등 분배 금지**.

## 씬 분할 — One Scene, One Point
- 각 씬은 **단 하나의 주장**만 담는다. 두 가지를 말하려 하면 씬을 쪼갠다.
- 오프닝·클로징 = 감정/각인, 중간 씬 = 논리.
- 통상 **5~8개 씬**으로 수렴한다. 씬 수가 이를 크게 넘으면 메시지가
  파편화된 신호이고, 밑돌면 씬 하나가 과적된 신호다.

## 시간 예산 배분 — Time Budgeting
- 전체 길이를 **중요도 순**으로 나눈다. 균등 분배 금지.
  핵심 논증(절차·실증)에 길게, 개념 씬은 중간, 감정 씬(오프닝)은 짧게.
- 씬별 시간 = **기본 낭독 시간 + 여백**. 텍스트 글자 수로 최소 표시
  시간을 자동 산정할 수 있고(게이트 2의 원리), 내레이션 예정이면 대사
  타이밍 여유를 추가 확보한다. 낭독 실측(TTS)이 나오면 실측이 정본이다.
- 표준 예시 배분 (90초 / 7씬):

| 씬 | 역할 | 길이 |
| --- | --- | --- |
| 오프닝 | 각인 | 8s |
| 문제 | 필요성 | 13s |
| 개념 | 해법 | 11s |
| 절차 | 작동 방식 | 18s |
| 차별점 | 차별화 | 13s |
| 실증 사례 | 신뢰 | 15s |
| 클로징 | 결론·CTA | 12s |

이 배분이 씬 템플릿 7종의 권장 길이 기본값이다.

## 착지 — 구체 증거와 행동 유도
- 막연한 주장 대신 **구체 식별자·수치**로 신뢰를 확보한다 (보고서 번호,
  실측값, "전문가 6인 만장일치" 같은 검증 가능한 사실).
- 마지막 씬은 반드시 **행동 유도**로 닫는다 — 진입점·다음 단계를 명시한다.

## 실무에서 왜 중요한가
scenario_build R3에서 MO의 dur 배분 발의를 심사하는 기준이다 — 배분안이
중요도 가중을 반영했는지, 낭독 시간 + 여백이 확보됐는지를 이 카드로
대조한다. "씬 하나에 절차와 차별점을 같이 넣자"는 patch 요청은 One Scene
One Point 위반으로 반려하고 씬 분할을 역제안한다. 전반부 절차는
[ST-C-001] 참조.
