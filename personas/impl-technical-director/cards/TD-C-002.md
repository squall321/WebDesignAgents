## 정의
mp4 인코딩은 엔진 파일에 없다 — 호스트(또는 자체 exporter)가 seek →
캡처 → 인코딩 루프를 구현한다. 이 카드는 exporter가 지켜야 하는 대기
계약과 폰트 인라인 메커니즘의 정본이다.

## 3단계 대기 — 이 순서를 지켜야 캡처를 시작할 수 있다
1. `svg[data-om-exportable-video-with-duration-secs]` **마운트 대기** —
   x-import의 전역 폴링(50ms 간격, 30초 타임아웃)이 완료되어 씬 트리가
   렌더되었다는 신호다. duration도 이 속성값에서 읽는다.
2. `document.fonts.ready` 대기 — 웹폰트 로드 완료.
3. `svg[data-om-fonts-inlined="true"]` 대기 — 엔진이 페이지의 모든
   @font-face 규칙을 foreignObject 내부 `<style>`로 복사하고 폰트 URL을
   **data: URL로 치환** 완료했다는 신호. 이 단계를 건너뛰고 캡처하면
   SVG 직렬화 프레임에서 한글이 깨진다.

## 실행 전제
- **http 서빙 필수** — x-import와 폰트 인라인이 fetch 기반이라 file://
  로는 동작하지 않는다. 로컬 정적 서버로 서빙한다.
- CDN(unpkg·jsdelivr) 접근 가능 환경이거나, 엔진 로드 전에
  `window.__resources`(URL 치환) / `window.__resourceBlobs`(Blob 프리로드)
  를 주입해 오프라인 번들로 대체한다 — 렌더 노드 네트워크 격리의 표준
  주입 지점.

## 프레임 루프
- t = i/fps마다 seek 이벤트(`detail:{time:t, sync:true}`) dispatch 후 즉시
  캡처한다. sync-seek 미지원 시 rAF 2회 대기 폴백.
- 캡처는 svg 요소 스크린샷(Playwright) + `[data-omelette-chrome]{display:
  none}` CSS 주입으로 재생 바 제거. 뷰포트는 1920×1080 + 크롬 여유로 잡아
  CSS scale 왜곡을 회피한다.
- 인코딩은 Playwright 프레임 PNG + ffmpeg 조립(권장, 단순) 또는 페이지 내
  WebCodecs VideoEncoder(Chromium 전용).
- 중첩 비디오/오디오 믹싱 정보는 `data-om-exportable-video-play-start/
  end/speed` 속성으로 전달된다.

## 실무에서 왜 중요한가
export 결함 신고의 대부분은 대기 계약 위반이다 — "글자가 깨진다"는 3단계
생략, "첫 프레임이 비어 있다"는 1단계 생략, "로컬에서 안 돈다"는 file://
서빙이 전형 원인이다. 심의에서 캡처 절차 단축·병렬화 제안이 오면 이
카드의 단계를 어느 것도 생략하지 않는지 심사한다. seek 자체의 결정성
계약은 [TD-C-001] 참조.
