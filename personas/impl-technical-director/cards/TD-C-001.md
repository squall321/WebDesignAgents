## 정의
렌더 엔진(support.js + animations-v2.jsx, 무수정 재사용)의 저작 계약 중
구성·결정성에 관한 3개 조항. 심의에서 구현성 판정의 정본 근거다.

## 조항 A — OM_SCENES/OM_PLAYBACK 제약
- 씬 목록은 반드시 메인 문서의 vanilla 인라인 `<script>`에 **JSON 문자열
  리터럴**로 선언한다 — `window.OM_SCENES = '[{"name":"오프닝","dur":8},…]'`
  — 그리고 SceneStage `scenes` prop에 문자열 그대로 전달한다.
- 게스트 측 검증기 ssParse의 상한: 전체 16KB 이하, 씬 1~50개, 각 `dur`는
  0 초과 300 이하의 유한수. 위반 시 null 반환으로 기존 구성이 유지된다.
- `OM_PLAYBACK`은 `'{"mode":"loop"}'` 또는 `'{"mode":"times","count":N}'`
  (N은 1~99). ppParse가 전량 엄격 검증한다.
- 씬 `name`은 SceneStage 자식 컴포넌트 맵의 키와 **정확히 일치**해야 한다
  (게이트 1). 엔트리의 여분 필드(예: `stills`)는 검증 없이 `scene` prop으로
  무가공 전달된다 — 스키마 확장 지점.

## 조항 B — localTime 순수성
- 활성 씬은 props로 `{localTime, progress, dur, index, count, scene}`을
  받는다. 모든 시각 상태는 **localTime/progress의 순수 함수**로만 계산한다.
- 금지: `Date.now`, `Math.random`, `setTimeout`/`setInterval`, `useEffect`
  기반 상태 전이, 자체 rAF 루프 (게이트 6의 정적 AST 린트 + 이중 seek
  픽셀 동일성 런타임 검사 대상).
- 타임 스트레치: 엔트리의 `nat`(자연 길이) 기준 `stretch = nat/dur`,
  `localTime = wallTime × stretch`. dur를 늘리면 같은 안무가 느려진다 —
  안무를 자르지 않고 배속이 조절되는 구조.

## 조항 C — seek 결정성
- 프레임 seek는 `svg[data-om-exportable-video-with-duration-secs]` 요소에
  `CustomEvent('data-om-seek-to-time-frame', {detail:{time, sync:true}})`를
  dispatch한다. 엔진이 `data-om-sync-seek="true"`를 광고하면 flushSync 동기
  커밋으로 dispatchEvent 반환 직후 DOM이 해당 프레임 상태다.
- unmarked seek(export 프레임 포함)에는 overlap 전환이 개입하지 않아
  프레임당 정확히 한 씬만 렌더된다.
- 순수성(조항 B)이 지켜져야만 같은 time에 대해 항상 같은 화면이 나온다.
  **결정성은 영상 export와 PPT 정지 캡처가 같은 코드 경로를 공유하는
  전제**이며, 이를 깨는 요구(재생 이력 의존 연출, 랜덤 파티클)는 절대
  거부권 대상이다.

## 실무에서 왜 중요한가
씬 55개 분할, setTimeout 지연 등장, 매 재생 다른 랜덤 배치 같은 제안은
전부 이 카드의 조항 위반으로 즉시 판정 가능하다. 거부 시에는 계약 안의
대안(씬 병합, localTime 조건 분기, 고정 시드 좌표 배열)을 함께 제시한다.
export 파이프라인 대기 계약은 [TD-C-002] 참조.
